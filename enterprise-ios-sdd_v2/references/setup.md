# Setup: bootstrap, layout, and tech stack

## Bootstrap

From the target repository root:

```bash
/path/to/enterprise-ios-sdd_v2/scripts/sdd-bootstrap
```

It creates or merges the project `.sdd/` files, agent adapters (`AGENTS.md`, `agent/`), templates, `scripts/sdd-*`, the `Makefile`, and CI workflow templates. Existing files are kept unless `--force` is passed. If the repository already has an equivalent structure, reuse it instead of creating a second one.

Done when every file `sdd-validate` requires exists and `tech-stack.md`, `tech-stack.yaml`, `constitution.md`, and `architecture.md` contain project facts rather than `TBD`.

## Canonical layout

```text
.sdd/
├── constitution.md
├── project/            objective, tech-stack (.md + .yaml), architecture, engineering-rules,
│                       security, performance, quality-gates, release
├── features/
│   └── FTR-###-name/   spec, clarify, checklist, plan, tasks, test-plan, execution.yaml, status.yaml
├── adr/                ADR-###-*.md
├── traceability.yaml   generated by scripts/sdd-status
├── mcp-registry.yaml
└── quality/            definition-of-ready, definition-of-done, execution-rules, release-readiness
agent/                  workflow.md, review-rules.md
templates/              feature/, project/, quality/, adr.md
scripts/                sdd-* commands
AGENTS.md
Makefile
.github/workflows/      sdd-validation.yml, release-readiness.yml
```

The templates in `templates/` are the source of truth for each file's sections.

## Tech stack

`.sdd/project/tech-stack.md` is the human-readable record of approved technologies; `.sdd/project/tech-stack.yaml` is the machine-readable contract used by automation and MCP recommendations. Keep both in step.

Record, for each: platform and minimum OS, Swift and Xcode versions, UI frameworks, architecture style and dependency injection, concurrency model, networking, persistence, dependency manager with approved and prohibited SDKs, unit/integration/UI testing tools, lint/format/static analysis, CI/CD provider, observability, feature flags, and media stack where relevant.

A tech-stack change can change MCP recommendations; re-run `./scripts/sdd-mcp-recommend` after editing either file.
