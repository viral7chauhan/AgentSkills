# Definition of Ready

A feature is READY for technical planning only when the following are sufficiently clear.

- [ ] Objective is clear
- [ ] Problem is understood
- [ ] Scope is explicit
- [ ] Non-goals are explicit
- [ ] Functional requirements have stable IDs
- [ ] Acceptance criteria have stable IDs
- [ ] Important edge cases are identified
- [ ] Error states are identified
- [ ] Dependencies are identified
- [ ] Architecture impact can be assessed
- [ ] Security/privacy impact considered
- [ ] Accessibility considered
- [ ] Localization considered where applicable
- [ ] Analytics/observability considered
- [ ] Performance/reliability considerations identified
- [ ] Rollout/rollback considerations identified
- [ ] Open questions are either resolved or explicitly accepted as low-risk assumptions
- [ ] Test strategy can be defined for the acceptance criteria
