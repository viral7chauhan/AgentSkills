# Feature Readiness Checklist: FTR-###

## Specification
- [ ] Objective is clear
- [ ] Scope is clear
- [ ] Non-goals are explicit
- [ ] Functional requirements have stable IDs
- [ ] Acceptance criteria have stable IDs
- [ ] User flows are clear
- [ ] Edge cases are identified
- [ ] Error states are defined

## Engineering
- [ ] Architecture impact assessed
- [ ] Applicable ADRs identified
- [ ] Dependencies identified
- [ ] Security/privacy considered
- [ ] Accessibility considered
- [ ] Localization considered where applicable
- [ ] Analytics/observability considered
- [ ] Performance/reliability considered
- [ ] Rollout/rollback considered

## Validation
- [ ] Test strategy covers acceptance criteria
- [ ] Traceability can be established
- [ ] Open questions resolved or explicitly accepted
